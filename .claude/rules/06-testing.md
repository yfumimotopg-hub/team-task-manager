# 06. テスト

## 完了前チェック（必須の運用）

- **完了前に、変更に関連するテスト・利用可能な型チェック・lint をローカルで実行する。**

```bash
# frontend
pnpm test
pnpm lint

# backend
uv run pytest
uv run ruff check .
```

- **型チェッカが未決定の場合、未導入の型チェッカを勝手に選定・導入しない。**
  Python の型チェッカは ADR で決定する（[04-backend.md](04-backend.md)）。**決定後は CI で実行する。**
- **失敗した場合は隠さず、出力とともに報告する。** 勝手に無視・先送りしない（[08-workflow.md](08-workflow.md)）。
- **テストを削除・skip・アサーション弱体化して「通す」ことは禁止**（[09-guardrails.md](09-guardrails.md)）。

## テストを書く範囲

- **新機能・バグ修正にはテストを追加する。**
- バグ修正は「**失敗する再現テストを書く → 修正する**」の順で行う。
- カバレッジは目安として扱い、数値ノルマより **重要パスの網羅** を優先する。
- カバレッジ閾値は ADR で決定する。

## バックエンド（pytest）

- service / repository の単体テスト + API 統合テスト（HTTP クライアント経由）。
- **テスト DB は使い捨て**（トランザクションロールバック、または都度作成・破棄）。
  **本番 / 開発 DB へ接続しない。**
- テストデータは factory で生成する（ライブラリは既存パターンに従う。未定なら ADR）。
- AAA（Arrange / Act / Assert）で書き、1 テスト 1 検証を基本とする。

## フロントエンド（Vitest + Testing Library）

- **振る舞い視点**で書く（ロールやラベルで要素を取得し、実装詳細に依存しない）。
- API はモックする（モックライブラリは ADR / 既存パターンに従う）。
- スナップショットテストは最小限にする。

## E2E

- E2E ツールは将来 ADR で決定する。現時点では対象外。

## CI

- CI では lint + テストを実行する。型チェックは型チェッカ決定後に追加する。
- CI の必須化範囲・内容は CI 設定側で管理する（このファイルは方針のみ）。
