# 09. ガードレール（人間レビュー必須 / 勝手に変更してはいけないもの）

このファイルは [08-workflow.md](08-workflow.md) の「確認の要否」の判断基準となる具体リスト。
目的は AI を縛ることではなく、**不可逆な事故と一貫性の崩壊を防ぐこと**。

## 着手前に人間と合意が必要（または PR で必ず人間承認）

- **DB スキーマ変更のうち、既存データに影響するもの**（下記「DB スキーマ変更の線引き」参照）
- **認証・認可・セッション・トークン・パスワードハッシュ**に関わる変更
- **個人情報**の取り扱い・保存・ログ出力・エクスポート
- **API の破壊的変更**（既存レスポンス形状の変更、エンドポイント削除、必須パラメータ追加）
- **CORS / CSP / セキュリティヘッダ / レート制限** の設定
- **依存パッケージ**のうち: 本番ランタイムに影響する新規依存 / 認証・認可・セキュリティ関連の依存 /
  メジャーバージョンアップ / 大規模な依存関係変更
  （テスト用・lint/format 用・型生成/開発補助などの軽微な開発依存は自律追加可。
  その場合も「なぜ必要か」「既存の依存で代替できないか」を確認してから追加する）
- **インフラ / CI / デプロイ設定**（`docker-compose.yml`, CI ワークフロー, 環境変数の追加）
- **公開設定・feature flag のデフォルト値** の変更
- **アーキテクチャ変更**（レイヤ構成・依存方向・ディレクトリ規約・主要ライブラリ）
- **広範囲に影響する変更**（共通クエリ、インデックス、キャッシュ戦略、共有コンポーネントの破壊的変更）

## DB スキーマ変更の線引き

いずれの場合も **Alembic を使う** / **適用済みマイグレーションを編集しない** /
**`--autogenerate` の差分を人間が確認する** は変わらない（[05-database.md](05-database.md)）。

**Claude Code が自律的に進めてよい:**

- ユーザーが承認済みの仕様に基づく新規テーブル追加
- 既存データを破壊しない新規 nullable カラム追加
- Rule / ADR / 既存設計に沿った通常のスキーマ追加

**着手前に人間確認が必要:**

- カラム削除
- カラムリネーム
- 型変更
- 既存データの変換・移行
- 既存データに影響する NOT NULL 追加
- destructive migration
- 大量データや本番運用に影響する migration

## Claude Code が勝手に行ってはいけないこと

- `main` への直接コミット、`git push`、`git push --force`、タグ付け、リリース（[07-git.md](07-git.md)）
- `.env` / secrets / 認証情報の作成・変更（`.env.example` への項目追加は可、値は空にする）
- **適用済み Alembic マイグレーションの書き換え**（[05-database.md](05-database.md)）
- ロックファイル（`pnpm-lock.yaml`, `uv.lock`）の理由のない変更・削除
- lint / 型チェック / フォーマッタ設定の **ルール緩和**
  （`strict` 解除、`any` の全面許可、lint 無効化コメントの多用）
- 既存の公開 API 契約（OpenAPI）の後方互換を壊す変更
- **テストの削除・skip・アサーション弱体化で「通す」こと**（[06-testing.md](06-testing.md)）
- 本番 / 開発 DB への直接接続・破壊的操作
- 大量の自動生成物や無関係ファイルを含む一括コミット
- **未決定の重要技術選択を、ADR なしに Rule やコードで既成事実化すること**
  （認証方式、非同期方針、主キーの型、スタイリング手法、Python 型チェッカ、
  OpenAPI 型生成ツール、ページネーション方式、エラーレスポンスの具体形 など）

## 判断に迷ったら

- **変更を止めてユーザーに確認する。デフォルトは保守的に。**
- ただし軽微な実装判断まで逐一止めない。既存パターンに沿って進め、報告で差分を説明する
  （[08-workflow.md](08-workflow.md)）。
